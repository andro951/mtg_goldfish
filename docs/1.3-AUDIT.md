# Astra 1.3 audit and verification notes

## Review of the preceding changes

The 1.2.1 inspector, mode-preference, choice-revision and additional-cost changes were reviewed against their actual source and exercised again through the browser. The accepted behavior is:

- A rejected or cancelled activation leaves the inspector available. A completed tap or self-sacrifice activation closes it; a repeatable KCI activation does not. Leaving the inspected zone closes inspection, including KCI sacrificing itself and a hand card being plotted.
- A saved Raft-Steerer mode can be bypassed for one trigger using Modes, without changing the saved preference. Dependent targets are rebuilt, and the next trigger uses the saved preference again.
- Scene of the Crime selects the creature paying the additional tap cost before asking for the produced color. Choosing that cost is not a premature irreversible payment; cancelling the unfinished activation restores the original state.
- Moonsilver Key's regression test is retained: KCI is eligible, Radiant Lotus is not. No incorrect mana-ability reclassification was introduced.

Three additional edge cases were corrected during review: Retreat does not offer its creature mode without a legal creature target; Scaretiller does not offer its graveyard mode without a legal land target; Raft-Steerer mode availability respects targeting restrictions such as shroud instead of merely counting creatures. Their explicit state assertions are in `tests/programs.test.js`.

The importer was also found to repin related token printings during ordinary verification. It now retains a named definition already present in the pinned snapshot. Two ordinary import runs with network requests disabled produced identical data hashes. An explicit developer `--refresh` still requests a refresh, including rulings.

## Geometry and owned slots

A card's saved corner is the upright bottom-left. Clockwise +90-degree rotation is performed about the card's physical bottom-right, translated left by one card width. That physical corner therefore occupies the saved anchor. The tapped screen rectangle extends right from the anchor; its bottom is unchanged. Browser checks assert the matrix direction and transform origin as well as the rectangle, so a counterclockwise rectangle lookalike no longer passes.

Graveyard, exile and outside-the-game grids use per-incarnation slot arrays. Manually positioned objects release their slots. Slots do not depend on card rectangle overlap. Grid reset writes real layout positions and ownership, and is undoable. Export/import and HTTP reload tests cover detached positions and grid state.

## Performance changes and measurement

The old selector rebuilt the full table and its image-heavy HTML on each selection. The new selector updates selected classes and counts in place. Embedded art is converted once to reusable compact blob URLs; the canonical card and save state still contain local paths. Characteristic construction avoids repeatedly cloning immutable metadata. Pointer movement is coalesced per animation frame, drag previews are created once per gesture, and preview motion uses composited transforms. Autosave serialization is deferred while a drag is active. Unrelated game events no longer trigger automation preference serialization or a second full-table redraw.

A same-machine Chromium comparison rendered each authored standalone edition, imported the same 49-permanent fixture through the actual session UI, and timed real selection-button handlers after animation frames. Each edition supplied 50 measured samples after 10 warm-ups:

| Edition | Median handler | 95th percentile | Maximum |
| --- | ---: | ---: | ---: |
| 1.2.1 | 99.9 ms | 102.7 ms | 108.7 ms |
| 1.3.0 | 0.3 ms | 0.3 ms | 0.5 ms |

These numbers measure the synchronous selection handler in that fixture, not total frame time or every possible gameplay operation. The reproducible script is `tools/benchmark_tabletop.py --baseline /path/to/older/Astra-standalone.html`. Structural acceptance additionally checks stable table/gallery nodes across selections, one reused preview throughout a drag, and no residual preview after release.

## Player-program safety

User automations are optional data, not arbitrary executable code. They use normal legal engine intents at clean priority boundaries. The engine preflights an entire sequence iteration in an isolated state and commits one real atomic action only after that succeeds. A failed late command rolls the entire iteration back. The tests cover missing resources, incomplete recordings, ambiguous cross-game card copies, changed stack objects, undo/redo and deterministic replay.

An atomic line cannot silently skip a configured before-resolution rule or postpone another matching priority-boundary rule past subsequent recorded actions. Preflight rejects that conflict before changing the real state and asks the player to split the line or disable that rule. Rules and iterations are bounded to prevent accidental self-triggering chains: 256 recorded commands, 1,000 requested iterations, and 100 chained rule executions. Holds only apply when the stack is nonempty. Stop acts between complete iterations.

Current-stack shortcuts retain exact stack IDs. Game-only sequences and rules travel with that game's export but do not automatically appear in new games. Future rules retain referenced sequences, and enable/disable state is preserved. The import/export layer is not an anti-cheat or cryptographic authentication system.

## Release evidence

`test-results/engine.tap`, `browser.json`, `portable.json`, `release.json` and `package-verification.json` are generated from the actual release run. The local in-memory browser mode is useful for authored UI testing but explicitly skips HTTP storage/download/file-navigation checks. It is not sufficient for release: packaging requires the full HTTP/direct-file report with no failures, errors, external requests or skipped checks, plus the isolated offline portable-file test.

The full source archive includes tests, editable modules, local assets and a per-entry SHA-256 manifest. A completed release must rebuild both HTML editions byte-for-byte from those modules and validate the archive contents independently.
